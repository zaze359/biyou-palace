## 一、背景与目标

碧游宫 V1.0 的服务端已经收口：NewAPI 网关、准圣/散仙节点、阵图、灵脉、道鉴与一键 Compose 部署均已可用。但日常使用仍依赖浏览器、curl 或各节点自带页面，缺少一个**双击即用、面向内网用户**的桌面入口。

本任务交付「碧游宫客户端 V1」：

- macOS / Windows 桌面应用；
- 连接碧游宫网关，使用统一 OpenAI 兼容入口；
- 可选连接本机准圣节点；
- 复用 dsh 的 Agent / 会话 / 模型管理能力；
- 以「碧游宫」品牌呈现，数据只在内网流转。

**一句话验收**：内网用户安装客户端，填入网关地址与令牌，即可选择模型、流式对话并保存会话；换到本机准圣模式也能直接使用。

## 二、目标用户与场景

| 用户 | 场景 | 期望 |
|---|---|---|
| 内网普通用户 | 日常问答、写作、代码辅助 | 不记 curl / 端口，打开即用 |
| 集群使用者 | 使用碧游宫统一入口 | 模型列表来自网关，按网关策略路由 |
| 单机用户 | 没有网关或网关不可达 | 直连本机准圣 `4010` 继续工作 |
| 运维人员 | 排查客户端问题 | 能看连接状态、日志、配置目录 |

## 三、范围

### 3.1 V1 必须交付（P0）

| 编号 | 能力 | 说明 |
|---|---|---|
| F1 | 首次启动引导 | 选择「网关模式 / 本地模式」，填写 URL 与令牌，测试连接并拉取模型 |
| F2 | 网关接入 | 默认 `http://127.0.0.1:3000/v1`，也支持任意内网 NewAPI 地址 |
| F3 | 本地准圣接入 | 默认 `http://127.0.0.1:4010/v1`，令牌可选；探测 `/v1/health` |
| F4 | 模型选择 | 从 `/v1/models` 拉取，允许勾选与设置默认模型 |
| F12 | 模型元数据 | 引导页「高级设置」可编辑上下文窗口、最大输出、图片能力 |
| F5 | dsh 运行时 | 应用内启动 dsh Web 运行时，加载其 Agent / 会话界面 |
| F6 | 品牌壳 | 应用名「碧游宫」、图标、窗口标题、菜单、关于页 |
| F7 | 配置持久化 | 重启保留网关地址、模型选择；API Key 加密存储 |
| F8 | 连接状态 | 显示网关/本地节点可用性；失败给出可操作错误 |
| F9 | 退出清理 | 退出应用后不残留 dsh / Node 子进程与端口 |
| F10 | 打包产物 | macOS arm64 + x64（dmg/zip）、Windows x64（NSIS），V1 不签名 |
| F11 | 诊断入口 | 打开日志目录、配置目录；可复制连接诊断信息 |

### 3.2 V1 可选（P1）

| 编号 | 能力 | 说明 |
|---|---|---|
| F13 | 一键切换网关/本地 | 不重启应用切换已保存的两套配置 |
| F14 | 诊断包导出 | 打包脱敏日志与版本信息 |
| F15 | 局域网访问说明 | 文档说明 NewAPI 仅绑定 `127.0.0.1` 时的限制与改法 |

### 3.3 明确不做（Out of Scope）

- ❌ 不做碧游宫集群管理台：渠道增删、节点注册、阵图任务、Grafana 看板仍走现有入口。
- ❌ 不把 Ollama、准圣 Python 服务、模型权重打进安装包。
- ❌ 不内置模型下载 / 模型市场。
- ❌ 不做自动更新、代码签名、公证、MSIX；V1 产物未签名。
- ❌ 不做多网关账号体系、团队空间、云同步。
- ❌ 不修改 dsh 上游源码；V1 以已发布运行时为依赖。
- ❌ 不承诺 dsh Desktop 的全部原生能力（托盘、文件拖拽、麦克风权限等）。

## 四、关键约束

1. **客户端不是节点**：V1 不启动 Ollama，也不启动准圣服务；本地模式只连接已在运行的准圣。
2. **只走内网**：默认只连 `127.0.0.1` 或内网地址；不向公网暴露客户端运行时。
3. **dsh 版本固定**：V1 绑定一个已发布 dsh 版本，升级必须单独验证。
4. **密钥不落明文**：API Key 不得写入 YAML、日志或诊断信息。
5. **不破坏现有服务**：本任务不修改网关、节点、阵图、监控的行为。
6. **Windows 构建在 Windows 上完成**：macOS 不能交叉产出可用的 Windows 安装包。

## 五、验收标准

### 5.1 功能验收

- [ ] 全新安装后首次启动进入引导，可完成「网关模式」配置。
- [ ] 错误令牌返回明确提示（401/403），不崩溃、不静默失败。
- [ ] 网关不可达时提示检查地址/服务，并可返回修改。
- [ ] 成功拉取模型列表，能选择默认模型并进入对话。
- [ ] 高级设置可修改上下文窗口与最大输出，重启后保留。
- [ ] 对话为流式输出；模型切换后新会话使用新模型。
- [ ] 重启客户端后保留网关地址、模型选择与登录状态。
- [ ] 「本地模式」能连接 `http://127.0.0.1:4010/v1`，`/v1/health` 为 ready 时可对话。
- [ ] 退出应用后 `dsh` / Node 子进程退出，监听端口释放。
- [ ] 菜单可打开日志目录与配置目录；日志中不出现明文 API Key。

### 5.2 打包验收

- [ ] macOS arm64 产出可启动的 `.app` 与 `.dmg`。
- [ ] macOS x64 构建脚本可用（在 x64 机器或 CI 验证）。
- [ ] Windows x64 构建脚本与 CI 可用（在 Windows runner 验证）。
- [ ] 安装包内含 dsh 运行时与 Node 运行时，无需用户预装 Node。
- [ ] 关于页显示客户端版本、dsh 版本、Electron 版本。

### 5.3 回归验收

- [ ] `bash scripts/verify.sh` 通过。
- [ ] `.venv/bin/python -m pytest zhentu -q` 通过。
- [ ] 本任务不新增对服务端运行时的依赖，不修改现有 Compose 行为。

## 六、成功指标

- 新用户从安装到发出第一条消息 ≤ 3 分钟。
- 正常内网环境下冷启动到可输入 ≤ 10 秒（不含模型首 token）。
- 客户端异常退出后无孤儿进程；连续启动/退出 10 次无端口泄漏。
